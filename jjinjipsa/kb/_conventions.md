# KB 작성 기준 (자체 합의)

> `_template.md`가 문서 **구조**를 정한다면, 이 파일은 필드에 **무엇을 넣을지**의
> 판단 기준을 정합니다. Tier 2·3 확장 시에도 이 기준을 따릅니다.
> 최초 작성: 2026-07 (Tier 1 15개 완료 후 리뷰 반영)

---

## category — 카테고리 매핑

`_disease_list.md`의 카테고리가 `_template.md`의 허용값에 없으면 **침범 장기 기준**으로
매핑한다. (허용값: urinary/gi/infectious/endocrine/cardiac/respiratory/dental/skin/eye/
msk/neuro/oncology/behavior/emergency)

| 리스트 카테고리 | 매핑 | 근거 |
|---|---|---|
| 기생충 (내부기생충) | `gi` | 소화기 증상으로 검색되므로 |
| 기생충 (벼룩) | `skin` | 피부 증상(가려움·탈모)으로 검색됨 |
| 기생충 (심장사상충) | `cardiac` | 심장·폐혈관 침범 |
| 혈액 (빈혈·IMHA) — Tier3 | `cardiac` | 허용값에 `blood` 없음 → 침범 계통(순환기)으로 매핑. 의미상 완벽하진 않으나 규칙 준수 우선 |
| 순환기 (고혈압) — Tier3 | `cardiac` | 순환기 = 심혈관 계통 |
| 외상 (낙상) — Tier3 | `emergency` | 허용값에 `trauma` 없음 → 응급 처치 계열로 매핑 |

## breed_risk — 품종 소인

리뷰에서 "파일마다 상세도가 다르다"는 지적이 있어 기준을 통일합니다.

**기재 규칙**

1. **여러 문헌에서 반복 보고되는 품종만** 기재한다. 단발성 보고나 추정은 제외.
2. 최대 5개까지. 그 이상이면 국내에서 실제로 흔한 품종을 우선한다.
3. 소인이 뚜렷하지 않거나 근거가 약하면 **`[]`로 비운다.** 억지로 채우지 않는다.
4. 성별·나이가 주된 위험 요인이고 품종은 무관한 질환은 `[]`.
   (예: 요도폐색은 수컷이라는 점이 핵심이지 품종이 아니다)
5. **합병증 관계인 질환은 원인 질환의 목록을 따른다.**
   (예: ATE는 HCM의 합병증이므로 HCM과 동일한 품종 목록)
6. 위험이 **낮다고** 보고된 품종은 기재하지 않는다.
   (예: 갑상선기능항진증에서 샴·히말라얀은 오히려 위험이 낮다는 보고 → `[]`)

**적용 결과 (Tier 1~2, 35개)**

| 기재함 | 비운 이유 |
|---|---|
| CKD, 요로결석, URI, HCM, ATE, 당뇨병, 헤어볼, 링웜, 천식, 결막염, 각막궤양, 치주질환, 관절염 | 나머지는 품종 소인이 뚜렷하지 않음 (규칙 3·4·6) |

## age_risk / sex_risk

- `kitten / adult / senior / all` 중 **가장 발병이 집중되는 구간 하나**만 고른다.
- 전 연령에 고르게 발생하면 `all`. 굳이 좁히지 않는다.
- `sex_risk`도 마찬가지로, 유의미한 편차가 있을 때만 `male`/`female`.

## urgency_level

- **반드시 `_disease_list.md`의 이모지 태그와 일치시킨다.** 임의로 올리거나 내리지 않는다.
- 🔴=red / 🟠=orange / 🟡=yellow / 🟢=green

## 경과 관찰 섹션

- **red 등급은 관찰 조건을 쓰지 않는다.** 다음 문장으로 고정한다:
  > 이 질환은 경과 관찰 대상이 아니에요. 의심되면 즉시 병원으로 가세요.
- yellow/green은 관찰 조건 + **전환 조건**("이렇게 되면 즉시 병원")을 반드시 함께 쓴다.
- **orange는 원칙적으로 관찰 조건을 쓰되, 시간 단위로 악화하는 질환은 red와
  동일하게 처리한다.** 등급을 올리지 않고 관찰 섹션만 즉시 병원 안내로 쓴다.

  현재 예외 적용 문서 (2건):

  | 문서 | 등급 | 예외 사유 |
  |---|---|---|
  | `eye/corneal-ulcer.md` | orange | 하루 이틀 사이 궤양이 깊어지면 시력·안구 상실 위험 |
  | `infectious/fip.md` | orange | 치료 시작 시점이 예후를 좌우, 관찰 권고가 위험 |

  이 두 건은 `observe_ok_conditions`도 `[]`로 비워 챗봇이 관찰을 제안하지
  않도록 했다.

## 근거 수준이 불확실할 때

- 단정하지 말고 불확실하다고 **명시**한다. ("자료가 적지만 안전하다고 볼 근거도 없어요")
- 애매하면 **병원 상담 쪽으로 유도**한다. 챗봇의 기본값은 안전 쪽이다.
- 단일 요인으로 환원해 설명하지 않는다.
  (예: 칼슘옥살레이트를 "산성 소변" 하나로 설명 ❌ — 여러 요인이 함께 작용)

## 면책 문구 표준

문구가 화면마다 갈리면 어디선가 빠져도 눈에 띄지 않는다. **새로 만들지 말고
`lib/disclaimer.ts`에서 가져다 쓴다.**

| 상수 | 쓰는 곳 | 문구 |
|---|---|---|
| `DISCLAIMER_CHAT` | 챗봇 답변 마지막 ℹ️ 블록 | 저는 참고 정보를 드리는 것이고, 진단과 처방은 수의사 선생님의 영역이에요. |
| `DISCLAIMER_UI` | 화면 하단 고정 (카드·폼·입력창) | 이 정보는 참고용이며, 정확한 진단은 수의사 상담이 필요합니다. |
| `DISCLAIMER_SHARE` | 앱 밖으로 나가는 산출물 (공유 건강카드) | 위 문구 + "응급 신호가 보이면 바로 동물병원으로 가주세요." |

**삽입 규칙**

1. **모든 챗봇 답변에 예외 없이** ℹ️ 블록을 붙인다. 레드플래그 고정 응답도 포함
   (`lib/redFlags.ts`가 `DISCLAIMER_CHAT`을 사용한다).
2. KB 문서는 `## 출처` 섹션으로 근거를 밝히고, 챗봇이 답변할 때 위 문구가 붙는다.
3. **green 등급 문서에서 특히 주의.** "관찰해도 된다"가 "진료를 미뤄도 된다"로
   읽히지 않게, 관찰 조건과 **전환 조건**을 반드시 함께 쓴다.
   ("경과 관찰 섹션" 규칙 참고 — 이것이 안전장치다)
4. 문구를 바꿔야 하면 `lib/disclaimer.ts` 한 곳만 고친다.

## 수의사 감수 워크플로우

각 문서 frontmatter에 `draft` 필드가 있다.

```yaml
reviewed_by: 자체 작성
draft: true      # 감수 전 = true
```

**감수 완료 시**: `reviewed_by`를 감수자명(면허 기준)으로 바꾸고 `draft: false`로,
`last_reviewed`를 감수 연월로 갱신한 뒤 `npm run kb:index`를 다시 돌린다.

**감수 우선순위** — 50개를 한 번에 감수하기 어려우므로 **red/orange부터** 진행한다.
`npm run kb:index`가 미감수 red/orange 목록을 출력한다 (현재 21건).

**감수 완료분만 참조하도록 전환**: 환경변수 `KB_REQUIRE_REVIEWED=1`을 켜면
챗봇이 `draft: false` 문서만 참조한다. **현재는 감수 완료가 0건이라 꺼져 있다**
(켜면 KB 참조가 통째로 사라진다). 감수가 끝나는 대로 켤 것.

그때까지는 화면의 참고 자료 목록에 "아직 수의사 감수를 받기 전이에요"가 함께
표시된다.

현재 Tier 1~2 총 35개는 **자체 작성 상태**이며, 아래가 완료되기 전에는 의료 정보
서비스로 공개하기에 적절하지 않습니다.

| # | 항목 | 상태 | 조치 |
|---|---|---|---|
| 1 | **수의사 감수** | ❌ 0/50건 | 위 "수의사 감수 워크플로우" 참고. **red/orange 21건 우선.** 완료 후 `KB_REQUIRE_REVIEWED=1` |
| 2 | **출처 상세 URL 확정** | 🟡 115/149건 (전 문서 최소 1개 확보) | 2026-08-02 반영. 50개 문서 전부가 질환별 딥링크를 최소 1개 갖는다. 남은 34건은 해당 기관에 그 질환의 소비자용 페이지를 찾지 못한 경우로, **기관 대표 페이지를 그대로 두고** 파일 상단 주석에 어느 출처가 미확인인지 적어뒀다 |
| 3 | 면책 문구 노출 | ✅ 적용됨 | `lib/disclaimer.ts` 단일 출처. 챗봇 답변·레드플래그 응답·건강 카드에 표시 중 |
| 4 | draft 플래그 | ✅ 적용됨 | 50개 전부 `draft: true`. 화면에도 "감수 전" 표시됨 |

**2번 방법**: Cornell·MSD·icatcare는 모두 봇 요청을 403으로 막기 때문에 페이지를
직접 열어 확인할 수 없습니다. 대신 **검색 인덱스로 존재와 제목을 확인한 URL만**
기재했습니다. 주소 패턴이 규칙적이라 추측할 수 있어도, **확인되지 않은 URL은 쓰지 않습니다.**

남은 34건을 억지로 채우지 않은 이유: 예를 들어 Cornell에는 낙상·열사병의 고양이용
소비자 페이지가 없고(개 페이지만 있습니다), MSD에는 턱드름 단독 페이지가 없습니다.
없는 페이지를 비슷한 주제로 대체하면 출처가 근거를 뒷받침하지 못하게 됩니다.
