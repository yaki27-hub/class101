# 기록 동기화(계정 보관) 켜는 방법

> 관련 결정: DECISIONS.md **D-16**
> 코드는 준비돼 있고, **환경변수 하나만 켜면 동작한다.** 다만 작업 환경에서
> Supabase에 접근할 수 없어 실제 서버 대상 검증은 하지 못했다. 아래 순서대로
> 확인하면서 켜는 것을 권한다.

---

## 지금 상태

| 항목 | 상태 |
|---|---|
| Supabase 스키마·RLS | ✅ 적용됨 (T-14, `supabase/migrations/0001_init.sql`) |
| SupabaseStorageAdapter | ✅ 구현됨 (T-16) |
| 익명 로그인 | ✅ 동작 (D-09) |
| 카카오 로그인 시 uid 유지 | ✅ `linkIdentity` (D-16) |
| 로컬→서버 1회 이관 | ✅ 구현됨 (D-16) |
| **동기화 활성화** | ❌ **꺼짐** — `NEXT_PUBLIC_USE_SUPABASE` 미설정 |

동기화가 꺼져 있는 동안 기록은 **브라우저에만** 저장된다. 그래서 지금 UI는
"이 기기에만 저장돼요"라고 안내한다(문구가 이 플래그를 따라간다).

---

## 켜기 전 준비 — Supabase 콘솔에서 확인할 것

1. **Authentication → Providers → Kakao**가 켜져 있고 키가 들어가 있는지
2. **Authentication → URL Configuration**의 Redirect URLs에 배포 도메인이 있는지
   (예: `https://jjipsa.vercel.app`)
3. **Authentication → Sign In / Providers → Anonymous sign-ins**가 켜져 있는지
   (D-09에서 쓰고 있음)
4. **⚠️ Manual linking이 켜져 있는지** — `linkIdentity`가 이 설정을 요구한다.
   꺼져 있으면 익명 계정 승격이 실패하고 새 계정 로그인으로 폴백되어,
   **익명으로 쌓은 기록이 계정에 붙지 않는다.** 이 항목이 가장 중요하다.

---

## 켜는 순서

1. Vercel → 프로젝트 → Settings → Environment Variables

   ```
   NEXT_PUBLIC_USE_SUPABASE = 1
   ```

2. 재배포 (환경변수는 빌드 타임에 들어가므로 재배포가 필요하다)

---

## 켠 뒤 확인 (이 순서대로)

### 1) 게스트로 기록이 서버에 올라가나

- 시크릿 창으로 접속 → 고양이 등록 → 증상 기록 하나 남기기
- Supabase → Table Editor → `cats` / `symptom_logs`에 행이 생겼는지 확인
- 실패하면: RLS 정책 또는 익명 로그인 설정 문제

### 2) 카카오 로그인 시 기록이 유지되나 ⭐ 가장 중요

- 위 상태에서 **카카오로 로그인**
- **로그인 후에도 등록한 고양이와 기록이 그대로 보여야 한다**
- Supabase → Authentication → Users에서 해당 유저를 보면
  **같은 uid에 카카오 identity가 추가돼 있어야 한다** (새 유저가 생기면 실패)
- 실패하면: 위 준비 4번(Manual linking)을 확인

### 3) 다른 기기에서 이어지나

- 다른 브라우저·기기에서 같은 카카오 계정으로 로그인
- 기록이 보이면 성공

### 4) 예전 기록(동기화 켜기 전에 쌓인 것)이 올라가나

- 동기화를 켜기 전부터 쓰던 브라우저로 접속
- 자동으로 1회 이관이 돌아간다. 개발자 도구 콘솔에
  `[migrate] 로컬→서버 이관 {...}` 로그가 찍힌다
- `failed: 0`이면 성공. 0이 아니면 완료 표시를 남기지 않으므로 다음 접속에 재시도한다
- **로컬 원본은 지우지 않으므로**, 문제가 생겨도 플래그를 다시 끄면 원래대로 보인다

---

## 되돌리기

`NEXT_PUBLIC_USE_SUPABASE`를 지우고 재배포하면 즉시 localStorage 모드로 돌아간다.
이관 과정에서 로컬 데이터를 지우지 않기 때문에 **기록은 그대로 남아 있다.**

---

## 알려진 한계

- **이미 다른 기기에서 카카오로 가입한 계정**이 있는 상태에서, 새 기기에 익명으로
  기록을 쌓은 뒤 같은 카카오로 로그인하면 `linkIdentity`가 실패한다(그 신원이 이미
  다른 계정에 붙어 있으므로). 이때는 기존 계정으로 로그인되고, 새 기기의 익명 기록은
  자동으로 합쳐지지 않는다. 로컬에 남아 있던 기록은 이관 로직이 올려주지만,
  **서버에만 있던 익명 계정 데이터는 합쳐지지 않는다.**
  계정 병합이 필요해지면 별도 설계가 필요하다.
- 이관은 브라우저에서 순차 업로드라, 기록이 아주 많으면 시간이 걸린다.
