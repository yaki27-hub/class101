# 찐집사 개선 작업 지시서 (2026-08-06, 실사용 로그 기반)

> 사용자가 배포본(jjipsa.vercel.app) 실사용 로그를 검수해 전달한 지시서.
> 원문 요지를 보존하고, 각 항목의 **코드 진단 결과**와 진행 상태를 여기서 관리한다.
> 태스크 번호는 TASKS.md M7 (T-40~).

컨텍스트: 경쟁 서비스(픽케어)는 강아지 전용 + 일회성 Q&A. 찐집사의 우위는
**"기록을 기억한다 + 트리아지 판정"** — 이 두 축의 정확도 결함을 최우선으로 잡는다.

## P0 — 신뢰를 직접 깨는 버그

### 1. 개체 혼동 (Critical) — T-40
달씨 상담창에서 "로마 비만일까?" → 응답 전체가 달씨 기준(4.3kg 인용).
- 진단: 선택된 catId 컨텍스트만 주입하고, 질문 속 다른 개체명을 보지 않았다. 사실.
- 수정: ① `Cat.aliases` 필드(프로필에서 편집) ② 전송 전 이름 매칭 → 개체 확인 UI
  ③ 시스템 프롬프트 하드 룰(R8): 다른 개체 지칭 감지 시 판정 대신 확인 질문만
- 완료 조건: 교차 지칭 시 확인 프롬프트, 회귀 테스트(`npm run test:mention`)

### 2. 프로필-응답 간 체중 불일치 — T-41
프로필 4.5kg vs 챗 인용 4.3kg.
- 진단: `weight_logs`는 이미 있음(D-19). 그런데 **프롬프트에는 `cat.weightKg`
  스칼라만** 들어가고 측정일이 없었다. 예전 대화 히스토리의 낡은 수치를 모델이
  재인용해도 바로잡을 근거가 프롬프트에 없었던 것.
- 수정: 프롬프트에 최신 측정치+측정일 주입, 인용 시 "4.4kg(6/8 기준)" 형식 강제.
  프로필 표시값은 이미 체중 기록 저장 시 동기화됨(D-19)

### 3. 트리아지 판정 오분류 — T-42
몬스테라 예방 문의·경미한 활동 저하·헤어볼이 🔴로 남발.
- 진단: 몬스테라·활동저하·털토는 **룰이 아니라 LLM이 낸 🔴** (룰 엔진에는 해당
  패턴이 없음). 백합·이물질 🔴는 룰 발동으로 정상.
- 수정: ① 룰 앞단에 **예방·정보 문의 인텐트 가드** (노출 사건 없으면 룰 미발동,
  단 노출 표지가 있으면 가드 무시 — 애매하면 상향 원칙 유지)
  ② 프롬프트에 예방 문의 취급 규칙 + 🔴 남발 금지 명시
  ③ 판정 근거 1줄 노출 ④ 추적: 룰 판정은 `model:"rule-engine"`으로 이미 저장됨
  (별도 컬럼 대신 이 필드가 triage_source 역할)
- 완료 조건: 지시서 5케이스 재분류, 응급 룰 골든셋 100% 🔴 유지

### 4. 일일 한도가 응급 후속을 차단 — T-43 (2주차)
- 이번 주 반영: 한도 메시지에 응급 안내 병기 (완료)
- 남은 것: 🔴/🟡 후속·개체 정정 쿼터 제외 — 서버가 스레드 판정 상태를 알아야
  해서(클라이언트 플래그는 위조 가능) 서버 측 설계 필요. 잔여량 상시 표시 포함
### 5. 지난 상담 카드 클릭 무반응 — T-44 (2주차, 원인 조사부터)
